### What the subagent built (its report, checked against the diff)
- **Validate** (`judge/validate/validate.go`, `reference.go`, `judge/cmd/judge/validate.go`): `judge validate [-structure-only] [-strict] <problem-dir|problems>`. Structural checks need no sandbox; the reference check judges every `solutions/<lang>/<verdict>.<ext>` through the engine (behind a `Judger` interface) and requires that verdict, with an `ac` solution per language. Exit 0 valid, 1 invalid, 2 usage or host error (no root/nsjail: `ErrNoSandbox`). `make validate-problems [DIR=...]`.
- **Version change detection** (`api/internal/store/rejudge.go`): `SyncProblem` reads the old version under `SELECT ... FOR UPDATE` and upserts in one transaction, returning `ProblemChange{Slug, Created, Old, New}`. Old bundles stay in object storage (keys include the version).
- **Rejudge** (`store.BeginRejudge`, `store.PendingRejudge`, `api/internal/rejudge`, `api/cmd/rejudge`): one statement per batch with `FOR UPDATE SKIP LOCKED` selects judged rows whose verdict version differs from the problem's, plus queued or judging rows on an older version, sets `test_set_version` to the current one, status `queued`, `enqueued_at` NULL, and returns id, language, source. The routine enqueues a job with the new version in batches of 100, then `MarkEnqueued`. A failed enqueue leaves `enqueued_at` NULL so the existing reaper retries it. Run at API start after the problem sync for every problem whose version changed (`api/cmd/api/main.go`), and on demand with `go run ./api/cmd/rejudge [-dry-run] [-batch N] <slug>` (built as `bin/rejudge` by the e2e script).
- **Verdict write rule** (`api/internal/store/verdicts.go`): a verdict for a version other than the submission's current one is dropped; a stored verdict is replaced only when the incoming version equals the submission's current version and differs from the stored one; duplicates and same-version conflicts change nothing; an `IE` never replaces a real verdict (it only moves a requeued row back to `judged`, so a failed rejudge keeps the old verdict).
- **Bug found while designing it:** the Redis marker `<prefix>:verdict:<id>` was keyed by submission id only, so a rejudge job would have been acknowledged as "already judged" and its result dropped. `queue.Publish` and `queue.Published` now scope the key to the test-set version (`Published(ctx, id, version)`); the runner passes the job's version (`runner/internal/agent/agent.go`), and an `IE` result carries the job's version.
